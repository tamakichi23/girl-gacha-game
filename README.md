# きらめきポスト ✧

手紙を開いて、20人のオリジナルキャラクターと出会うブラウザガチャゲーム。React + Viteで実装した、サーバーやAPIキーが不要のシングルプレイ版です。PC・スマートフォン対応。

## 起動

Node.js 22以降（動作確認: Node.js 24）を使用します。

```bash
npm ci
npm run dev
```

開発サーバーはポート5173で起動します。クラウド環境でホームディレクトリのnpmキャッシュに書き込めない場合は、`npm ci --cache /tmp/kirameki-npm-cache` を使ってください。

```bash
npm run build    # dist/ に静的サイトを出力
npm run preview  # ビルドしたサイトをポート4173で確認
npm test        # ゲームロジックの8テスト
npm run test:e2e # Playwrightによるブラウザ操作テスト
```

E2Eテストの初回は `npx playwright install chromium` でブラウザを導入してください。既存のChromiumを利用する場合は `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`。テスト用サーバーは自動起動します。

## 遊び方

- 最初に6,000きらめきを所持。単発300、10連2,700。
- R 80%・SR 17%・SSR 3%。SSR内50%がピックアップの星宮ひかり。
- 初回10連はSSR1人確定。通常10連はSR以上1人確定。
- SSRが49回続けて出なければ50回目で確定。単発・10連で共通の天井。
- 封筒をタップして1人ずつ登場。演出スキップで結果をまとめて確認できます。
- 重複は60きらめきと親密度に。出会い2・3・5・10回で親密度アップ。親密度3でキャラクターごとの特別な台詞が解放されます。
- 各抽選で独立して4%のホログラム加工。図鑑にも保存されます。
- 毎日1,500きらめきの贈りもの。通貨欄の「＋」から30秒ごとに3,000を無料補充できます。課金・広告はありません。
- コレクションはレアリティ、所持、お気に入り、名前・個性で絞り込み可能。

保証は最後の抽選を置き換えます。通常確率・保証時の確率と優先順位はゲーム内の「提供割合・ガチャのルール」で確認できます。

## 保存と素材

進行はブラウザのlocalStorageに自動保存します。同じオリジンの同じブラウザで継続できます。設定からJSON書き出し・読み込みでバックアップや引き継ぎが可能です。プライベートブラウズの終了やブラウザデータ削除で消えるため、必要な進行は書き出してください。アカウント・クラウド同期はありません。

キャラクター設定とSVGイラストは本プロジェクト用のオリジナルです。全員20歳以上。日本語フォントは同梱したNoto Sans JP / Noto Serif JP（SIL Open Font License）、アイコンはLucide（ISC）を利用しています。実行中の外部通信は不要です。フォントライセンスは `public/licenses/` に同梱しています。

## 構成

- `src/data.js` — キャラクター、プロフィール、親密度台詞
- `src/game.js` — 抽選、天井、保証、セーブ検証
- `src/Portrait.jsx` — SVGキャラクターイラスト
- `src/main.jsx` — ホーム、ガチャ演出、コレクション、設定
- `src/styles.css` — レスポンシブUI・演出・モーション軽減対応
- `src/game.test.js` / `tests/game.spec.js` — ロジック・ブラウザ検証

## GitHub Pagesへの公開

`main` にpushするとGitHub Actionsがテストを実行してビルドし、GitHub Pagesへ自動公開します。ビルド時にプロジェクトのサブパス `/girl-gacha-game/` を設定し、アイコン、JavaScript、スタイルシート、日本語フォントを正しく読み込みます。

公開URL: <https://tamakichi23.github.io/girl-gacha-game/>

初回のみ、GitHubのリポジトリ設定で **Settings → Pages → Build and deployment → Source → GitHub Actions** を選びます。公開が完了するとGitHub Pagesはブラウザから直接遊べるようになります。進行はプレイヤーのブラウザ内に保存され、同じブラウザ間での共有やクラウド同期はありません。

通貨・抽選はクライアントで完結するため、商用課金や競争要素を追加する場合はサーバー側管理が必要です。
